# 汉字魔法战 V2 北极星

机器可读约束以同目录的 `00-NORTH-STAR.json` 为唯一真源；本文解释其产品含义。当前状态是 `FOUNDATION_ONLY`，不是实施许可，也不是儿童验收。

## 玩家与体验承诺

核心玩家是约 6 岁、刚进入小学阶段的黄小越。她进入游戏时应该自然产生“我要去我的游戏世界冒险”的感受，而不是“爸爸又让我来练习”。儿童首屏首先呈现墨迹森林、英雄、墨点精灵、怪物、选择、魔法和能被修复的世界。学习目标、适合年龄、正确率、错题、练习次数和成人说明进入独立家长区或设置，不与冒险争夺第一注意力。

## 游戏幻想

墨迹森林正在褪色。黄小越是一位能听懂字灵的汉字魔法师；她与墨点精灵从字灵营地出发，把散开的汉字部件放回真实结构位置。完整汉字形成后，不是触发一段无关攻击，而是汉字本身显出读音、熟悉词和意义，再化为对应魔法，赶走墨怪并永久修复营地。

## 核心动作与学习如何发生

不可替换的核心是：**部件进入正确结构位置并组成完整汉字，这个动作本身就是施法。**

一次完整循环是：选择手牌中的字灵部件 → 放入左右、上下、包围或其他真实结构槽位 → 完整汉字形成 → 同步出现读音、熟悉词或意义 → 汉字转化为可读的魔法效果 → 世界或怪物发生变化。部件顺序、空间位置、字形、读音、词义与插图都必须一致。任何“先答题、再播放无关攻击”的实现都属于偏航。

## 为什么孩子会想继续

持续兴趣来自可理解的掌握、真正不同的选择、英雄能力差异、每局小变化、第一次施法的鲜明反馈、新字进入自己的魔法书，以及营地被永久修复。结束时应留下“下次我想试另一个能力”的期待，而不是利用登录天数、排名、损失厌恶或限时奖励制造压力。

## 技术方向

运行时锁定为 Vite + TypeScript + Phaser 3 + DOM overlay + localStorage + GitHub Pages。Phaser 负责世界、角色、战斗编排和视觉特效；可保存的规则状态必须独立于精灵、补间和 Scene 生命周期。文字密集的图鉴、设置、家长信息和可访问性控件使用 DOM overlay。存档仅在本地，具备版本、校验和温和恢复路径；不增加后端、账号或云端儿童追踪。

## 健康边界

禁止连续登录奖励、不登录损失、每日强制任务、无限抽卡、付费概率宝箱、排行榜、全球比较、连胜压力、失败惩罚性资源损失、FOMO 计时器和羞辱性失败语言。失败或撤退保留已获得的发现与永久进度，清楚给出可重新尝试的下一步。声音可关闭，静音仍能理解状态；非必要摇晃、闪烁和动画必须支持减少动画。

## 黄金样板范围

第一轮只验证 3–5 分钟的一条完整体验：两次点击以内进入游戏世界 → 看见字灵营地 → 墨点精灵用动作引导 → 第一场合字战斗 → 一次有意义的三选一 → 一个小首领 → 带回一个新字 → 修复一个营地物件 → 新字永久进入本地魔法书。

范围上限是 1 位英雄、1 位同伴、2 类普通墨怪、1 个小首领、1 次三选一、1 次营地修复，以及最多 12 个经成人审核的可玩汉字。首次成功施法尽量在 60 秒内发生。当前 V1 的 382+ 组合与更大牌库只作为候选母库，不自动成为低龄可玩内容。

## 明确非目标

本阶段不建设完整开放世界、多个区域、数十场战斗、数百项能力、多货币经济、复杂装备、宠物收集或大规模角色动画资产库；不迁移 Godot，不新建仓库，不修改其余游戏，不重做大厅，不把全部 UI 塞进 Canvas，也不把规则写进 Phaser Scene 回调。

## 扩建条件

只有自动测试通过、真实浏览器和代表性设备可用、关键视觉状态有截图证据，并且黄小越在少量提示下能完成第一次合字、理解三选一、注意到营地永久变化且观察结果支持继续扩建时，才允许提出 `PROMOTE`。代码完成、构建通过或 agent 自测都不能单独授权扩建。

## 停止或收缩条件

出现以下任一情况即停止相关子改动：孩子把过程理解成答题后领奖；无法自己判断第一步；真实结构被动画遮蔽；强反馈造成不适；新功能需要超出样板的大系统才成立；汉字内容准确性或适龄性无法确认；出现禁用留存机制、后端、Godot、第二种局外货币、超过 12 字、无 traceability 行或儿童试玩前的完整扩建。记录为 `REJECTED_FOR_NOW` 或 `NEEDS_USER_DECISION`，保留其他正常成果，再选择 `REVISE` 或 `STOP_AND_RETHINK`。

## 实现前四问

1. 它是否让黄小越更像是在玩，而不是做练习？
2. 它是否让合字本身仍然是核心动作，而不是被奖励系统遮住？
3. 它是否能在少量家长解释下被孩子理解？
4. 它是否避免焦虑、操纵、羞辱和强迫性留存？

任一回答为“否”或无法说明，都不得直接实现。
