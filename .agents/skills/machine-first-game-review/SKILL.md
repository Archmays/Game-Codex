# Machine-First Game Review

Use this Skill for root `AGENTS.md` lane 3, lane 4, or an explicit implementation acceptance/readiness request. Lane 1 retrieval and lane 2 bounded corrections follow their directly affected checks without entering this route. It owns the applicable machine QA; it does not create claims about unobserved real-child, parent, or teacher behavior.

Select checks from the actual changed behavior and affected consumers before mutation. The layers below identify risks to cover, not a requirement to exercise unrelated observer tools, every device, or historical release packages on every task. Shared saves, routes, privacy and other shared contracts retain their affected-consumer and negative-control checks. Apply `docs/input-contract.md` to changed inputs and supported actions. Public release, Pages verification, source freezes, closure packages and retention transactions apply only when the authorized route or handoff requires them; local development does not acquire publication authority from this Skill.

## Six review layers

1. Source and identity: establish the authorized question, changed paths, affected routes/catalog entries, accepted content, non-goals, and final source identity; create a formal freeze only when required.
2. Deterministic behavior: validate rules, persistence, migration, corrupt recovery, state invariants, and public transitions.
3. Browser lifecycle: validate route precedence, multi-page observer continuity, disconnect/reconnect, fallback, reload, history, stop, and conflicts.
4. Presentation and access: validate responsive layout, document scroll, keyboard/focus/targets, landmarks/headings/dialogs, reduced motion, and deterministic visual/ARIA states.
5. Runtime and privacy: require no console/page errors, explicit same-origin accounting, zero forbidden external requests, denylisted PII, and local minimum evidence.
6. Semantic review: apply the relevant child-first UX, visual/accessibility and adversarial QA rubrics to the actual result; use independent review when risk or an applicable gate calls for it.

## `DISCOVERY_MODE`

- Read applicable guardrails and discover the real source/evidence shape before relying on expected paths.
- Do not fail fast on a missing historical artifact when safe reconnaissance can establish the actual state.
- Complete semantic reconnaissance before the first product mutation.
- Establish known relevant findings, disposition, allowed dependency closure, stop condition, and authorized repair scope; use a frozen closure charter when required by the selected formal route.
- Treat references and candidates as non-accepted until exact-source acceptance proves otherwise.

See [recovery-and-source-freeze.md](references/recovery-and-source-freeze.md).

## `ACCEPTANCE_MODE`

- Fail closed on missing, stale, conflicting, or source-mismatched evidence.
- Run targeted dependency checks first, then the complete regression and browser matrix required by the selected scope. Preserve passing results when their source, dependencies and check conditions remain unchanged.
- Accept a visual/ARIA candidate semantically before baseline establishment, run no-update verification against that establishment, then seal promotion from both command records.
- Bind required evidence and semantic review to one unchanged final source tree; after a repair rerun affected checks and broaden only when the impact requires it.
- Derive reports and verdicts from canonical evidence rather than hand-written status.

See [lifecycle-and-evidence.md](references/lifecycle-and-evidence.md).

## Verdict

Emit exactly one:

- `PASS_MACHINE`: every hard gate passes, no Sev-1/2 or blocker remains, required profiles and matrices pass, no critical reviewer conflict exists, and final tests/build pass on the same tree.
- `AUTO_REVISE`: an authorized deterministic repair remains within the established dependency scope.
- `ESCALATE_HUMAN`: the remaining decision meets the evidence-based Human escalation conditions below; exhausting a fixed retry count is not sufficient.

## Auto-repair

Record each finding before mutation. Apply the smallest authorized repair, then rerun its dependency-affected logic, browser, semantic, and shared safety gates. A repair may close regressions it directly caused; it may not absorb unknown pre-existing product work, weaken gates, update baselines to manufacture a pass, or widen child data collection.

## Human escalation

When a repair fails, reclassify the root cause and change the test, implementation, or tool approach; do not stop because a fixed retry count was reached. Escalate only for real-child behavior the task genuinely depends on, value or preference choices, irreversible privacy/publication decisions, credentials or external permissions, or unresolved critical machine-reviewer disagreement. Provide one evidence-backed question and do not ask the user to perform routine UX, accessibility, browser, visual, or QA review.

## Phase closeout

After acceptance, deliver the changed source and the necessary validation result. For a formal release or requested handoff, also complete the applicable final freeze, same-tree evidence/report sequence, commit or deployed-build verification, return package and retention requirements. Do not add a freeze, ZIP, Pages readback or cleanup transaction to ordinary local work by default. Preserve protected human evidence and make no claim about child fun, learning, retention, or promotion from synthetic tooling.

See [retention-and-cleanup.md](references/retention-and-cleanup.md).
