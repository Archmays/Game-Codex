## 修前复现与根因

使用独立 Chromium 上下文，初始化匿名测试检查点，再通过普通页面启动、暂停、点选和拖放复现；没有调用内部 fuse 代替用户操作。

| 修前普通操作 | 实际结果 | 根因 |
| --- | --- | --- |
| 木→氵、山→火塔、林→山 | 三种逆序都禁用确认；已选两枚却仍显示“选两枚字核” | `recipeFor` 只匹配有序 inputs；预览与 model.fuse 共用这条错误选择规则，旧 controls 测试还要求先调换顺序 |
| 先火塔→山材料，对比先山材料→同一火塔 | 前者有范围圈且可合成；后者没有圈且不可合成 | scene 只查看 selection[0]；第一枚在背包时，无法查看第二枚场上塔 |
| 已选木、氵后再点火塔 | 原来的两个选择被整组重置为火塔 | 选择状态没有明确换搭档规则 |
| 山材料拖到已占火塔位 | 已准备山、火两枚，但落入同样的逆序无效预览；未自动吞塔 | 拖放路径依然受有序匹配限制 |

修前七条记录在 `before.json`，有范围／无范围代表帧已实际审阅。以上操作未发现事件丢失、点击拦截或页面异常；这不等同于已经复现所有设备上的旧问题。部署／合成后范围丢失另由清空 selection 的源码路径确认，并用修后自然操作回归覆盖。

## 实际修改

- 材料按两枚不同实体 ID 选择，按种类多重集精确匹配；`recipeCandidates` 和 `recipeFor` 同时服务搭档提示、规范预览、确认、拖放准备和快捷配方。唯一候选自动采用登记结构；多个登记候选必须选结果。保持九种字核、五条配方原文及数值，绝不将木氵或山火登记成新结构／产物。
- 一枚选择直接列出搭配、结果和具体缺料，并以文字及虚线标亮背包／场上搭档。两枚无效组合显示“暂无配方”，支持取消、重选和更换第二枚。缺料、重复 ID、失效来源或无效目标在 model 层也不消费。
- 目标独立于规范配方顺序：两枚背包回背包，背包与塔替换该塔，两塔明确显示保留与释放位置并可切换；拖放以落点塔为目标。model 同时拒绝无关第三塔、无关空位及不符合来源的背包目标。普通空位部署保持一次点击／拖放完成；已有塔位的合成必须再确认一次。
- 合成后选中产物并查看新范围；直接点亮起的搭档可以继续组合，点无关材料则开始新选择，不继承已消耗的搭档。取消选择按钮补足 44 CSS 像素高度。
- 查看状态、临时悬停／聚焦、部署预览与合成材料分离。桌面悬停、键盘聚焦及点选／触控均可查看塔；查看不消费、不部署，也不受第一枚背包材料阻挡。取消、收回、移位、升级及重开会清理或更新引用。
- 增加默认关闭、仅本页有效的“显示全部射程”。全部塔用轻轮廓，当前查看突出，空位预览用虚线；文字明确标出字塔名、攻击范围与塔位。开关不进入存档，也不改变战斗或选择。
- 射程由无输入捕获的 SVG 绘制，`viewBox=0 0 960 640`、`preserveAspectRatio=none`，中心取 SLOTS，半径直接取 CORES[kind].range；与 Phaser 地图及 DOM 塔位使用同一横纵比例。窄屏地图伸缩时圆相应变为椭圆，未猜测 CSS 半径或修改战斗数值。命中后的 splash 仍是独立效果。
- 在完整通关的结果页截图／重开检查中，捕获到 Phaser 自动缩放把临时零尺寸传给 WebGL，导致 `Framebuffer status: Incomplete Attachment` 和黑色战场。专门复现后改用本游戏战场元素的 ResizeObserver，仅同步正尺寸并在销毁时断开；不改变共享引擎或战斗步长。新增结果弹层、全页截图及重开的回归，检查画布内在尺寸与实际布局一致且无异常。

## 反思后再次实改

不再要求知道作者的点击次序；部署前能查看覆盖；错误组合直接说明原因和可换搭档。不过第一轮实现仍有一个查看顺序问题：鼠标停在氵塔上后聚焦火塔，实际仍显示氵的范围，见 `reflection-before.json`。已改为最新输入来源优先，并用真实聚焦、Tab 和鼠标路径回归。另补上移位预览时保留原塔的全部射程轮廓，使预览不会假装已经迁移。

发布前又用普通新局复查连续合成，实际发现“林已选中、山已点亮，但点山会丢掉林的选择”，见 `chain-review.json`。这会使界面搭档提示失实，因此补修 `freshResult` 分支：保留与新产物匹配的搭档，只有点无关材料或重新点产物时才开始新选择。新增桌面／触控连续合成回归；完整通关脚本按按钮真实选中状态选择尚未选中的材料，避免把已选产物取消。原提交 `2ec3f922666b7f1ddf2ad07e1101ef0e3c3e4a37` 的未完成发布已取消，再以正常追加提交发布补修，不重写历史。
