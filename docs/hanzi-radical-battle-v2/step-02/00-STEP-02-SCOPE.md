# STEP 02 范围：核心法术 Pilot 与家长审核

## 当前技术状态

`CORE_SPELL_PILOT_READY_FOR_PARENT_REVIEW`

这只表示本地代码和家长审核入口已经形成一个可检查的 STEP 02 技术对象。它不表示家长、教师或儿童已经接受，也不表示可以进入儿童试玩或 STEP 03。

## 本步骤唯一体验问题

在一个 60–90 秒的小闭环中，黄小越能否自然理解“把两个字灵放回真实结构位置”，并把完整汉字的形成感受为会永久改变世界的魔法，而不是一道题答对后的奖励？

这是一项待家长审核、之后再由真实儿童观察的问题；截图、自动化或成人代玩都不能回答它。

## 已实现且允许被审核的范围

- 一个隔离的 V2 核心法术闭环：营地暗灯 → 迷墨挡路 → 五张字灵牌 → 真实结构槽位 → 成字施法 → 灯修复 → 字灵书。
- 一个儿童主场景：`pilot-ming-left-right`，锚点是暂定的 `明 = 日 + 月` 左右结构。
- 两个仅供成人查看结构板的预览：`花` 的上下结构、`风` 的半包围结构；它们不是连续儿童关卡。
- 15 个可追溯候选字、三个程序化视觉方向、七格故事板，以及隐藏的本地家长审核工作台。
- 纯 TypeScript 规则状态、DOM 文字与结构操作层、Phaser 薄世界渲染、本地版本化存档、静音和减少动态设置。
- V1 仅做安全恢复文案修补；正式大厅与 V1 入口保持原样。

## 明确不在本步骤内

- 不实现完整 3–5 分钟黄金样板、第二场、正式 Boss、三选一、第二英雄或完整墨迹森林。
- 不把 15 个候选字变成 15 关；更不把候选直接升级为最终 `<=12` 个可玩 manifest。
- 不替换大厅、不把 V2 注册为默认儿童入口、不重构 V1 数据或战斗。
- 不生产最终精灵动画条、不批量生成正式美术/音频、不把 A/B/C 误写成最终美术选择。
- 不加入账号、联网存档、云端儿童追踪、广告、支付、排行榜、连续登录、抽卡、FOMO 计时器或惩罚性进度损失。
- 不开展儿童试玩，也不把技术检查称作儿童、家长或教师验收。

## 隔离边界

默认 URL 仍挂载现有游戏大厅。只有查询参数精确为：

```text
/?review=hanzi-v2-step02
```

才会动态加载 `apps/hanzi-v2-step02-review/`。该审核入口不在游戏目录、游戏卡片或正式儿童入口中出现。

## “明”锚点的证据边界

`明` 是 STEP 02 的 provisional anchor，不是已批准的儿童可玩内容。当前代码可验证的事实只有：

- V1 母库和 formula audit 都有 `日 + 月 → 明` 的 accepted 组合记录。
- V1 本地视觉提示为“明：明亮”；STEP 02 Pilot 采用“明亮”的熟悉词和光的魔法表现。
- V1 数据描述出现“明天”，与视觉提示的“明亮”不完全相同；STEP 02 已把该语义选择标为风险而非隐去。
- `日`、`月` 的显示部件、左右槽位和 `míng` 拼音都在候选记录中，但拼音、儿童熟悉度、适龄性、词义选择及结构呈现仍是 `pending-parent-review`。

它们不能证明字源、历史构形、儿童一定认识、孩子会喜欢，或最终 manifest 可收录。联想图只服务当前意义提示，不是字源说明。

## 接下来唯一允许的工作顺序

1. 完成技术复跑、浏览器和截图证据。
2. 家长在固定 JSON 中完成本轮决定。
3. 如有改动，只做 changed-only Round 2 审核。
4. 只有在另一次明确授权的任务中，才可讨论 STEP 03；本步骤没有授权 STEP 03。
