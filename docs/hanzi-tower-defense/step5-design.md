# 字阵守城 STEP5：战术短局

本批复用三张地图、既有素材与同一个固定步长战斗模型，新增六个可直接选择的三波短局。原战役三图二十二波、青岚九核五配方两共鸣、新图十一核七配方三共鸣和全部基础塔／敌人数值保持。目标是让玩家用有限材料比较覆盖与分工，再通过重整改变布局；机器结果不证明真实儿童乐趣、学习或实际三至五分钟体验。

| scenarioId | 地图／标题 | 主要差异 |
| --- | --- | --- |
| `qinglan-intercept` | 青岚／入口接力 | 前段密集团团怪、快怪追来、前后混合接力 |
| `qinglan-last-bend` | 青岚／末弯补漏 | 石甲先行、快慢错开、末弯接住穿过前排的怪物 |
| `twin-lanes` | 双岔／南北分守 | 同时双路、南快北重、双路群怪 |
| `twin-relay` | 双岔／轮换守望 | 北路为主→南路为主→分段轮转，波间可以搬塔 |
| `beacon-crowd` | 烽台／林箭清群 | 高密度群怪、穿插疾风、护甲穿群 |
| `beacon-captain` | 烽台／首领与护卫 | 护卫前行、集结、首领与护卫；沿用两次预告呼援上限 |

入口为 `?play=hanzi-tower-defense&scenario=<ID>`，优先于 `map`；只选择检查点或固定新局。标题旁“战术短局”列出六局和现有波次。战役入口继续保留，切玩法先保存；未完成的波会整体回到出发前。已有槽的明确重开与短局结果页“再守一局”均有确认。原战役结果页沿原重玩语义继续保留配方。

青岚短局起始火×3、木×3、氵×2、山×2；其余短局木增加为五枚。全部从材料栏开始，没有额外预制高级塔。每波第1／5次击败获得两枚固定材料：第一、三波依次木／火，第二波山／氵。波表在开战前列出路线分配、敌型与数量、中文及英文奖励；没有统一加血替代路线／密度／资源设计。短局更早提供现有英文：第一波火山共鸣、第二波山林共鸣，新图第一波另有森林共鸣；每种每局一枚，击败领取和波尾保底共用同一 grantId。

短局开波旁一直显示“战中可首次部署、合成和首次装备；已部署塔移动／收回与英文转移等波间。暂停仍在战中。”`deploy` 和 `stow` 的短局分支直接拒绝战中搬塔，失败不消费；已有合成和首次装备继续可用。射程检查仍独立于选料。原战役移动／收回行为保留，英文转移继续遵循此前已有波间限制。没有增加塔种、字词免疫、答题锁、货币、联网或麦克风。

## 重整与最少本机记录

短局键是 `family-games/hanzi-tower-defense/tactics/v1`，按 scenarioId 保存 checkpoint、retryCheckpoint、发现配方和最近两次摘要。直接短局链接惰性打开战役存档，既不读取也不触发战役 v2→v3 迁移。旧键不写入短局结构。坏／未来短局原文不可写；每次保存比较上次读取的完整原始字符串，跨页旧写入者停止写入。Vault 精确登记由共享入口统一完成。

现有模型波尾会把 checkpoint 更新为下一波状态，因此不能拿它冒充刚完成波的开战前证据。短局独立保留真正 retryCheckpoint：战中／失败恢复当前 checkpoint，正常波间／胜利恢复刚完成波的 retryCheckpoint。恢复包含中文实体及冷却、英文归属及领取／跳过记录、所有经济ID、随机种子、城门、击败／漏怪与累计模拟时间；清空敌人、延迟伤害、根区、表现事件和波计时，回到未暂停准备态。重复重整和刷新都随同整套经济回滚，不能累计奖励。发现配方属于非经济记录，按既有原则保留。

摘要只保留该短局最近两次波尝试的波号、结果、击败／漏怪、城门前后值、时长、每路击败／漏怪／实际受损，以及波前各路覆盖百分比。覆盖按真实塔射程与道路每十地图单位采样计算并明确称“波前覆盖”；不把它说成伤害、胜率或漏怪的唯一原因。不记录身份、操作轨迹或排名。失败页优先聚焦重整，胜利页优先聚焦再守一局，恢复后焦点回开波按钮。

## 两种构筑和布局取舍

`tools/hanzi-tower-defense/step5-balance.ts` 只调用真实合成、收回、部署、开波与每50ms更新事务，不增加材料、不注入敌人或胜利。甲为火山／林（新图森林／火山），乙为炎／山林，并搭配现有减速材料。每局两构筑都不装备英文。劣势布局使用完全相同的初始资源、配方与奖励：单路只顾后段四塔位、双路只顾北路四塔位，剩余材料留背包；这是同资源布局比较，不是同数量已部署塔的受控单因素实验。

十二条合法无英文模型回放全部完成三波。各布局的每路覆盖、逐波击败、漏怪和耐久均在 `tmp/tasks/GAME-CODEX-STEP5/tower/tactics-model-balance.json`；没有主观战力评分。首领是否成功呼援会影响实际怪物总数，比较保留真实计数，不伪造统一分母。

只装备 forest 的独立回放中，南北分守出现69次真正第四目标命中，林箭清群71次，均没有回声喷发或根区。南北分守战斗139.60秒，对照151.75秒；林箭清群134.60秒，对照133.85秒，后者没有总体变快。第四目标确实受攻击，但不能据此声称每一场总耗时都更短。青岚入口的火山单共鸣产生42次延迟爆发，炎／山林路线的山林单共鸣产生45次根区，二者各自作用由真实事件证明，未改基础攻击／冷却、呼援上限和1×／2×语义。

## 六顶帽复看与实际修订

有限参考 [Ironhide 官方独立挑战说明](https://www.ironhidegames.com/News/Details/381) 中公开的禁卖塔／禁道具限制，借鉴先说明约束、再让玩家比较结果；不采用其排名或限时激励。[官方不同挑战模式说明](https://www.ironhidegames.com/News/Details/140) 只用于核对独立模式的可辨入口，不冒充本作三波布局来源。没有复制关卡、数值或素材。

| 视角 | 发现与已实改 |
| --- | --- |
| 白帽 | 首轮偏后布局只增加通关时间，不能证明耐久取舍；修订各短局投放压力，再以实际击败／漏怪／城门比较。每路计数由敌人的实际 lane 累计。 |
| 红帽 | 增加第九个系统按钮会让手机多一行；战术入口移到标题旁，保留原八个系统控件布局。失败焦点直接到重整，成功则到主要重玩动作。 |
| 黑帽 | 波尾覆盖 checkpoint 会破坏重整；新增真正 retryCheckpoint，补反复重整／刷新与英文守恒。短局结果重开增加确认。 |
| 黄帽 | 两种无英文构筑都能过，差布局既有失败也有带伤通关；不把作者布局变成唯一答案。 |
| 绿帽 | 森林额外目标与整体时间不是同一个指标；新增 forest-only 回放，保留林箭清群略慢的真实反例，不将全部共鸣效果归到森林。 |
| 蓝帽 | 首次普通UI诊断在共享开发更新期间回到波前，保留失败。全树停写后补波号递增／原文检查并完成同首局三波；最终全量浏览器另在同源冻结阶段执行。 |

## 当前验证边界

新增专属11项单测及塔防既有133项合计144项小规模诊断通过；完整新旧模型、槽隔离／CAS／坏未来值、移动限制、重整守恒和摘要边界有断言。全树 TypeScript 检查通过。首局冻结诊断真实键盘三波、主动刷新继续、保存及返回通过，实看了布局和胜利截图；日志为 `tower/first-slice-frozen.log`。这场自动化墙钟597秒，实际模型战斗118.8秒，余下主要是自动化键盘导航／构筑与验证开销；不把它写作真实儿童三至五分钟体验验证。

六短局各一场完整普通UI、两输入机制、自然失败重整成功、设备和兼容浏览器、最终构建及同SHA发布验证，以统一 `docs/step5-playtest-report.md` 和最终冻结证据为准；本设计记录不提前宣称这些门禁已经运行通过。三至五分钟是包含自由布阵的设计目标，无强制等待。保持未来“明确授权后游戏期间持续语音监听”方向，本轮不接麦克风／云端，也不以未来兼容性阻塞交付。
