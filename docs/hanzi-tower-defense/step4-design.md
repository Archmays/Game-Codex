# 字阵守城 STEP4 设计与定向验证记录

2026-09-08。接续现有 STEP3 共鸣与合成／射程热修；原青岚关路径、八个塔位编号、六波、基础数值及中文掉落算法保留。按后续明确反馈修订 3／7／8 号塔位的有效路段覆盖，并给相邻 6 号位留出操作间距，具体坐标与对照见下文。浏览器与最终发布结论由统一 `docs/step4-playtest-report.md` 及同源证据收口，这份记录不提前宣称正式机器验收通过。

## 内容、地图与儿童体验

问题是孩子能否在清楚的地图和操作区之间分配覆盖，自主比较单体与群体构筑，并清楚选择继续哪张图。学习价值是观察上木下林的森、完整森林词序及 forest 的具体义项；魔法不冒充字源。未加入语音、账号、货币、遥测或另一套战斗引擎。

| 稳定 ID / URL 参数 | 地图 | 波次 | 差异 |
| --- | --- | --- | --- |
| `qinglan-pass` | 青岚关 | 原 6 波 | 原 9 核、5 配方、2 共鸣；原一条弯路及投放不变 |
| `twin-bends` | 双岔湾 | 8 波 | 南北两条不同长度的来路；各波显式 lane 数组交替投放；两路入口、回射及共同后路可分工 |
| `beacon-keep` | 烽台关 | 8 波 | 长弯来路；第 8 波唯一首领，只有两次预告呼援，没有字种免疫或新的普通敌人 |

三个入口均为 `?play=hanzi-tower-defense&map=<ID>`。URL 只选择已有检查点或该图固定新局，不触发重置。新图固定提供火×3、木×5、氵×2、山×2，其中一枚火已在塔位 1；物品仍有独立 ID。不从其他地图带入资源。所有图使用同一地图坐标、引擎与语义事务。每张地图独立登记中文材料池、击败掉落里程碑及英文 grant／波次／击败数，当前有意保持原中文随机规则不变。

实际查看现有 meadow.png 后确认它只有草地、边缘植被与右侧城门，没有绘死道路。新地图复用这张现有批准素材，路径由模型配置绘制并与城门对齐，未复制旧路背景。新森／森林使用真实完整字体、可辨的三枝／林冠几何塔冠及多束叶箭，共鸣轮廓增加第四分枝；不会以生成图中文字替换规范字形。

## 新字与共鸣

已定向核对 [汉典森](https://www.zdic.net/hans/森)：sēn、品字结构、树木繁密义。记录的上部木／下部林，其下林再含左右两木；按这两个输入的规范位置重排，不把左右拼接木林显示为森。已核对 [汉典森林](https://www.zdic.net/hans/森林) 与 [Oxford forest](https://www.oxfordlearnersdictionaries.com/definition/english/forest) 的大片树木覆盖区域义。仅采用这一自然实体义，不采用阴森、森严或其他引申义。Oxford 带 `_1` 的初始地址直接访问失败，搜索定位到官方实际 forest 地址后采用该词条的索引定义；运行时没有外部词典请求。

| 新事务 | 结构及材料价值 | 模型行为 |
| --- | --- | --- |
| 木＋林→森 | 无序选取两实体，规范上木下林；原料合计三木价值 | 每 0.8 秒主箭 30、次箭 18，最多 2 个不同射程内目标，射程 205；无溅射、减速或地面区域 |
| 森＋林→森林 | 规范完整词序“森林”；合计五木价值 | 每 0.85 秒主箭 42、次箭各 27.3，最多 3 个不同射程内目标，射程 215；没有自动追踪射程外目标 |
| 森林↔forest | 第 3 波第 3 次击败，同 grantId 波尾保底，每图一枚 | 同一主伤害、次伤害、冷却和射程，最多目标由 3 增至 4；同一目标不吃两支箭，没有区域、减速、额外爆发或递归分枝 |

主次目标统一按到城门的剩余路程升序，再按实体 ID 排序。不同路径不直接比较原 distance。副目标也必须满足真实射程；多目标效果与山林的根区控制具有不同作用。

首领耐久／倒计时显示在战场下方，不遮塔；屏读消息仅在出现、预告、呼援阶段改变时发布，避免逐帧播报耐久。

旧关既不展示也不允许新配方，不投放 forest；旧 v1 已过波次仅跳过原有两组英文奖励。旧中文 RNG 和五枚掉落规则未改。两种新合成仍使用原有守恒事务，保留来源塔位选择、材料消耗、最大来源冷却继承和不可覆盖第三塔规则。

## 保存、重置与输入

新键为 `family-games/hanzi-tower-defense/v3`，结构是 `{version:3, activeMapId, maps:{[mapId]:{checkpoint,unlocked}}, preferences}`。检查点含稳定 mapId 和现有中文实体、英文归属／领取／跳过记录。每张地图是一个可选择的继续存档，设置共用。v3 不存在时先读取 v2，只有 v2 不存在才读取 v1，并只复制验证合法的旧值；原始 v2/v1 字符串不动。坏／未来 v3 不由旧值覆盖；写入前比较原始字节，跨页恢复改写使旧页面停止写入。

顶部直接提供新游戏、继续游戏和重置进度。新游戏列三地图；已存在的该图须确认重置，其他地图不变。继续游戏列实际保存的地图和下一波，空槽禁用。明确重置清除所选图波次、材料与配方发现，保留其他图和旧存档原文。结果页“再守一局”沿用原有重玩语义，保留发现的配方；它与明确的“重置进度”区分。战中切图先保存波前经济检查点，返回时明示未完成波次一起回滚，不静默丢资源。取消弹窗回到打开它的控制。

沿用 `docs/input-contract.md`。材料、八塔位和英文各一个 Tab 入口，方向键与 Home/End 区内导航，Tab 可退出。原生 Enter/Space 只激活一次，P 仅在守城上下文暂停，Esc 取消，中文输入法／编辑域／浏览器组合键受保护。输入生命周期清拖动与临时指向，迟到的中文 drop 必须仍匹配本页活动拖动 ID；取消后即使残留 dataTransfer 也拒绝部署。HTML 原生拖动在 dragstart 后正常发出 pointercancel，把指针控制交给 DnD；该交接保留 native token 到 drop／dragend，真正的 Esc、blur、hidden 仍清理，未开始原生拖动的 pointercancel 也清理。隐藏页保留既有自动暂停。触屏“只看射程”可查看塔而不改变选料。主要操作 48px，其余 44px；小屏自然滚动、safe-area、动态视口及横竖屏几何由集中浏览器验收记录。

### 本页 1×／2× 速度

按本次新增要求，顶部加入“速度 1×／2×”原生按钮，八个按钮在手机上沿用四列两行。默认 1×，Enter／Space、点击与触屏均调用同一切换操作；重按保护沿用输入生命周期。速度只存于挂载实例，不加入 Preferences、检查点或 v3；切图、明确重置、再守一局及重新挂载均回到 1×。

`DefenseScene` 对原有真实帧增量先保留 0.1 秒上限，再乘页面速度累积，始终逐次调用 `updateBattle(state, 0.05)`。不放大单步 dt，不改伤害、投放、随机掉落或存档语义。原有 battle／未暂停／页面可见守卫继续生效，暂停、隐藏或波间清除累计余量；UI 刷新与声音计时保持原墙钟节奏。怪物、攻击冷却、根区和首领两秒预告都按模拟时间同步加速。`data-speed` 与 `data-elapsed` 仅反映当前速度和模型累计秒数，供只读验证，不提供状态写入口。

单独 `step4-speed.spec.ts` 以真实键盘／鼠标／触屏测量短墙钟窗口内的 1×／2× 推进比、暂停零推进、切图／重置／刷新回到 1×、切速不改存档原文，并检查手机八按钮尺寸、两行与命中。两个设备项目通过，实际短窗比值约 1.96／1.99、暂停推进为零。脚本不注入状态或修改浏览器时钟；新图完整八波通关脚本均使用默认 1×。

## 定向模型检查与六顶帽实改

青岚关补充反馈实改：3 号 `(390,510)→(390,455)`，7 号 `(640,530)→(640,430)`，8 号 `(870,555)→(870,355)`；6 号 `(865,270)→(825,205)` 为相邻避让。编号及已存塔实体归属不变。`check-placement.ts` 用圆与道路各线段的精确交集衡量有效覆盖，并用相同起始资源、只部署一枚火的合法首波模型比较。火塔 3／7／8 覆盖为 `277.5→387.5 / 151.7→391.1 / 187.3→387.3`，击败数 `2→3 / 1→8 / 1→3`；6 号覆盖约减 3%，击败数保持 2，没有把明显劣势转给它。中央连续路段与末路截击仍有作用差异，几何长度不冒充总体伤害或玩家胜率。新增两项单测及键盘／触控实际搬塔、真实射程、九宽度点击区检查均通过；手机实看 8 号塔位在城门侧上方，未盖住道路中心。旧完整六波仍由统一发布门禁验证。

`tools/hanzi-tower-defense/step4-balance.ts` 用真实 fuse/stow/deploy/startWave/updateBattle 事务生成两图两构筑与正／反塔位对照，不增加材料、伤害、耐久，不注入胜利。新图两个构筑都在无英文条件下自然完成。单靶与移动群靶为明确标注的受控数值实验；移动群靶中的同源点是比较夹具，不冒充合法游戏塔位。实际波次另用合法独立塔位验证。森林单靶 30 秒伤害低于森＋林前体总和，其价值来自受限多目标，未承诺每次升级单靶均更高。
