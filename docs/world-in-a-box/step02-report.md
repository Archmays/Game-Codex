# 世界盒子 STEP02 · 德累斯顿 v0.2.0

本轮在原《窗边有风》旁加入同一底座上的德累斯顿木制城市。起点为 `main` / `fdfcf5aa4a2859fd78b9a25283d04b87f5479b11`，初始工作区干净。只改世界盒子及必要的入口、存档清单和检查消费者，没有制作第三个盒子。

## 可玩的内容

18个逻辑件，与 Blender 中的根节点、接口和进度一一对应；网格合并不影响逻辑件数。

|区域|自由拼装件|
|---|---|
|河边（5）|奥古斯都桥、轮桨船、黄色电车、码头、河岸树组|
|老城（5）|圣母教堂主体、钟形圆顶、森帕歌剧院、茨温格庭院长廊、冠门|
|校园（5）|贝耶尔楼主体、观测塔、SLUB地面建筑组、中央采光顶、校园自行车架|
|街区（3）|街屋组、面包店门面、长椅小景|

所有区域可直接打开，不锁拼装顺序。圆顶、观测塔先装时有实体承托；错误匹配保留选择，重复提交不增加件数。提示调整观察方向，不代放。每页三件、区域相机和实际网格遮挡共同限制接口显示。

电车在轨道上真实移动，三个玩具目的地可选；无桥可以同岸行驶，跨岸停在桥前。装桥后手动继续；车在桥上撤桥时先安全回到老城。船沿河往返、轮桨旋转，可跟随及退出、暂停及继续、靠近已装码头。船不依赖先装桥或码头。撤船停止机关，撤停靠码头回到候船水域。所有移动变换与“已经拼好”事实分离。

SLUB有实际下凹空间、书架、桌椅、夹层走廊和采光顶。安装两个逻辑件后可展开、合上、返回全城；展开不增加进度。展开中撤销相关件会先关闭。屋面展开明确为玩具剖面，真实屋顶不会升降。

武汉、德累斯顿两只模拟表盘以同一设备时刻按 Asia/Shanghai 和 Europe/Berlin 计算，包括夏令时、跨日和分钟对时针的影响。表盘及完整日期时间可键盘聚焦阅读；日夜按钮只切换观赏灯光，不伪装实时天气或日落。

## 事实、画面与来源

官方建筑说明、运营方外观资料与 TU Dresden 官方静态校区地图用于核对。河流分两岸，桥连接老城/内新城，校园在南方，中间留街区和绿地；Beyer-Bau在SLUB以西。地标相对位置保留，距离、河道、楼层、桥孔数量和交通线明确简化。来源与逐项限定见 [dresden-sources.md](dresden-sources.md)。

桥、教堂、歌剧院、茨温格、Beyer-Bau和SLUB共六组实景对照，七张本地照片，SLUB含外观和内部。每组先显示当前木制模型，再显示照片、日期、作者及许可；照片可放大，退出恢复焦点。照片均为 Commons 可分发文件，许可版本和SHA在 `public/assets/world-in-a-box/dresden/photos/credits.json`。未用AI图冒充实景，未将仅供参考的官网照片打包。

复用了已有 Blender 4.5.14 LTS，没有再次安装。先由同一脚本导出教堂、桥和SLUB样件，在实际Three.js视图观察后再完成城市。正式 `.blend`、GLB、PBR木纹和可重跑脚本均交付；木纹嵌入资产，普通运行不需要Blender。相机依据导出包围盒和命名目标定位，机关枢轴及路线与建模同源。

新 `.blend` 清除了 Blender 序列化的本机文件浏览历史和原始纹理绝对路径；保留字符串字段长度、二进制块和打包纹理，随后用 Blender 重新打开确认18件与纹理仍完整。减少动态效果时，装配与剖面直接到达终态；交通只在主动出发后运行，可随时暂停。

完整可玩后进行了以下实际修订，并复验相关风险：

- 初版木色过曝，降低曝光和灯光，使教堂新旧砂岩、屋顶和木纹仍能分辨；深色石材是已完成建筑的一部分。
- 采光顶抬升后仍遮住阅览室，改为向后移并倾斜；冠门前的长廊开口重新留出，避免冠门埋在实体墙里。
- 先装观测塔时承托偏小，增加对应实体支撑；提示镜头增加正常俯仰/转角搜索，码头和主体接口不再只从被挡方向观察。
- 按网格高度复核任意顺序时，圆顶与未装主体的承托之间仍有细缝；补上圆顶下缘承托环，并对圆顶、观测塔的实际支撑间隙设断言。
- 交通与剖面操作原来离画面太远，增加画面下方就近操作栏；已装车辆的操作标记移到模型上方，以引线连接，避免盖住小车和船。
- 实际网格检查发现长椅背包侵入电车走廊，移动长椅与自行车架；最终按完整车体宽度复验。
- 最终高度复核发现石桥面盖住轨道，降低桥面与护栏至两岸一致的路面高度；用实际网格向下射线确认两条轨道露出，车轮不陷入桥面。
- 横屏连续点“提示→接口”会因滚动后同屏坐标接近，被浏览器记为双击。防重复处理改为仅针对同一拼装接口/物件，普通按钮保持原生逐次激活；滚动仅取消正在进行的手势。
- 关闭每帧无关接口射线工作，缓存夜景材质，静态结构按材质合并；保留真正可动的独立枢轴。
- 起点提交的公共入口命中检查已失败。本轮复现并读取浏览器 trace：点击后 `data-selected` 与可访问状态已改变，但通用取证函数串行的多次 DOM 往返超过其5秒轮询时限。将相同 URL、应用和控件签名合并为一次 DOM 读取，保持真实点击、命中检查及原有时限；随后复验公共入口矩阵。
- 完整公共矩阵进一步发现旧游戏百宝箱卡片缺少 `from=hub`，进入世界盒子后返回到了总大厅。参照仓库其他产品卡片补齐来源参数；默认直达入口仍返回总大厅，百宝箱卡片返回原百宝箱。

独立复核角度：内容/地理检查建筑识别轮廓、深浅石材、校园关系与简化提示；儿童操作检查自由选择、无惩罚反馈、拼好后可反复操作和就近控件；对抗检查取消、撤销、机关原子状态及异步加载生命周期。机器检查不代表真人儿童体验接受。

## 旧盒子与存档

仍只有一个 `world-in-a-box` 产品入口，默认旧盒子；`scene=dresden-river-campus`直达城市，“换盒子”可往返，未知场景有可见回退。两个场景按需加载，晚到GLB会释放，离开取消RAF、监听器、声音和GPU上下文。

旧 `family-games/world-in-a-box/v1` 保持原格式；城市为独立 `dresden-river-campus-v2` / schemaVersion 2。没有迁移旧档。城市重来、切换、加载失败与存储失败均检查旧字节不变；只在隔离浏览器上下文操作测试数据。未触碰家庭浏览器存档。

旧GLB仍为 `f6a8acfa5bb041e7ae0f2b047be5ebf4383a235f2a1dcaf483a7ad46f175d308`；旧模型、运行逻辑和音频源文件保持原字节。共享部分仅为资源释放、缩略图/基础相机及现有输入能力；没有重写旧机关。

机器结论：**PASS_MACHINE**。45个测试文件、569项单元测试通过；城市七组完整流程、项目子路径完整流程、旧盒子七组完整流程以及对抗/故障恢复检查通过。规范结果见 `step02-evidence/verification.json` 及其引用的实际操作记录。全城无更新重载的830400像素比较完全一致。

Windows x64、Node 24、真实Chrome浏览器；桌面键盘1440×1000、鼠标1366×900、触控390×844/360×800/844×390、平板768×1024/1024×768。触控为浏览器模拟，无物理手机实测。键盘从大厅开始，未用脚本focus或修改内部状态替代缺失操作；各输入组实际拼好18件。损坏/配额测试中的合成存档仅计为恢复证据。

离线验证采用新上下文、空缓存、浏览器请求层阻断外网并保留本地HTTP，从返回ZIP的迁移解压副本运行。覆盖固定 `127.0.0.1:5175` 和 `/Game-Codex/` 子路径；不是操作系统断网试验，不声明 `file://` 支持。沿用原有Node启动方式，不安装运行依赖。

远端首轮CI额外发现数学世界校验器仍按世界盒子加入前的三个大厅产品断言。补为四个明确产品ID的精确集合检查，并通过该校验器复验；游戏运行内容不变。首次推送后的必要消费者修复采用追加提交，不重写已推送历史，证据关联见 `step02-evidence/release-consumer-binding.json`。

随后独立CI的手机组在视口检查出现同类协议取证耗时：截图中的控件完整在屏内，但先等待ElementHandle再读取边界超过3秒。将边界谓词改为单次DOM查询，仍要求恰好一个控件、相同视口边界和相同3秒时限，并复验完整代表矩阵；不调整游戏布局或降低门槛。

后续清单与测试修复未改变游戏运行内容；离线ZIP只更新README中的源码身份，并逐项确认其余成员完全一致。最后的测试消费者关联记录见 `step02-evidence/ci-consumer-binding.json`。
