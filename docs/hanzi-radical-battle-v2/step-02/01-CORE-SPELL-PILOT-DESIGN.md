# STEP 02 核心法术 Pilot 设计

## 设计断言

部件进入真实结构位置并组成完整汉字，这个动作本身就是施法。STEP 02 用一个极小闭环验证这条断言的可审阅实现，而不是做“答对后播放无关攻击”的题目包装。

## 主场景：`明 = 日 + 月`

儿童主场景 ID 为 `pilot-ming-left-right`：

| 项目 | 当前实现 |
| --- | --- |
| 目标字 | `明`，候选 ID `ming`，左右结构 |
| 目标部件 | `日` → 左槽；`月` → 右槽 |
| 五张手牌 | 日、月、氵、亻、讠 |
| 卡牌操作 | 点一张牌再点槽位，或拖放到槽位；已放部件可点击拿回 |
| 手牌约束 | 对 V1 非空两/三部件组合枚举后，本手牌只命中“明” |
| 成字语义 | `明，míng。明亮的“明”。光从完整的字里出发。` |
| 永久变化 | 同一盏营地灯亮起，`明` 写入本地字灵书 |

手牌中的干扰项用于让“放到位置”成为实际动作，不扣血、不扣资源、不产生倒计时。无效放置会回到温和反馈；第二次后仅高亮一个相关槽位，不自动代放部件。

## 可见闭环

1. 营地灯暗，唯一主要动作是沿灯路出发。
2. 柔和迷墨挡住光，提示把字灵放回真实结构位置。
3. 进入五张手牌和左右结构槽；孩子可点按或拖放。
4. 最后一张目标卡归位时，`日` 与 `月` 先保持可见，再聚成完整的 `明`。
5. 完整字、拼音、熟悉词与“光”法术依次出现；迷墨柔和散开。
6. 光回到营地，原来的灯保持点亮，`明` 进入字灵书。

这条顺序是目前代码的状态和事件顺序，不是儿童理解已经被证实的结论。

## 规则、DOM 与 Phaser 的分层

### 规则真源：纯 TypeScript

- `simulation/pilot-machine.ts` 维护显式 phase、合法 action、温和重试次数、提示槽位和最小事件序列。
- `simulation/structure-board.ts` 只接受 `cardId → slotId`，验证未知卡、未知槽、已占用、重复放置和错误位置。
- 成字、法术、修复、字灵书等顺序由 `animation-complete` 推进，不由 Phaser tween 回调判定规则是否合法。
- `content/pilot-scenarios.ts` 是五牌、目标槽和成人结构 preview 的只读配置。

### DOM：文字密集和可操作表面

- DOM 负责手牌、结构槽、故事文本、字灵书、设置、家长审核和键盘/无障碍标签。
- 每个槽都有可读的空间标签，放入后能点击撤回；结构不是仅靠颜色提示。
- 设置可控制静音、减少动态、视觉预览方向和本机重置。

### Phaser：薄世界渲染

- Phaser Scene 只根据 `phase`、主题、减少动态和营地灯状态绘制营地、墨点、迷墨、法术和灯光。
- 现阶段为原创程序化 Graphics/CANVAS 表现；没有正式 sprite sheet、正式角色资产或最终美术验收。
- 减少动态时停止环境 tween；规则、完整字、文本、槽位和永久变化仍由 DOM/状态机保留。

## 标准与减少动态时间

从成字形成阶段到字灵书阶段的五段自动推进，当前每段定时为：

| 分支 | 每段 | 五段计划时长 | 无效放置反馈 |
| --- | ---: | ---: | ---: |
| 标准 | 470ms | 约 2.35 秒 | 340ms |
| 减少动态 | 125ms | 约 0.625 秒 | 250ms |

这些是当前定时参数，不是整个 60–90 秒闭环的实测耗时。进入、点选、拖放、停看文字和家长操作都会改变总时间；最终浏览器复跑时才记录真实值。

## 本地存档与隐私边界

存档 key 固定为：

```text
family-games/hanzi-radical-battle-v2-pilot/state
```

schema version 为 `1`，只保存：营地灯修复状态、字灵书 ID、静音、减少动态、审核主题和最小事件 ID。保存 schema 拒绝未知字段、重复字灵 ID、非事件文本或无效主题；损坏 JSON 回到安全默认值并提示本机记录已恢复。

没有儿童姓名、年龄、自由文本、音频、照片、账号、广告 ID、网络请求或远程 telemetry。最小事件仅用于本机技术复盘，不能单独解释兴趣或学习效果。

## 成人结构预览
