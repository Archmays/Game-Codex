## UI-only 合同

试玩规范只导入 `@playwright/test`，没有导入或调用关卡 solver、board reducer、catalog、生成器或关卡数据模块。每一步决策只读取页面可见 DOM，包括正式棋盘、提示文字、覆盖进度、反馈文字和可见控件状态。

测试开始时只清空 `localStorage` 以建立全新用户起点；它不注入进度、不写入棋盘状态、不伪造关卡完成状态，也不从运行时对象读取解答。所有状态变化均由以下可见 UI 输入产生：

- 可见上下按钮；
- 上方或下方相邻方块；
- 滑轨获得焦点后的键盘方向键；
- 鼠标真实按下、移动和释放。

## 证据边界

这轮证据证明：

- 正式教程必须通过真实棋盘动作才能推进；
- 25 个抽样关卡能仅靠公开 UI 完成；
- 三层动态提示能从当前可见状态持续给出可执行方向；
- 四种输入适配器能真实提交动作；
- 普通目标、多目标、等式和 2–5 滑轨拓扑都存在可完成路径；
- 错误反馈之后仍可继续完成关卡。

这轮证据不证明：

- 儿童能在没有提示的情况下独立理解或完成关卡；
- 儿童理解提示措辞、目标概念或错误反馈；
- 年龄分层、学习迁移、长期记忆或教学有效性；
- 儿童触控精度、手部疲劳、挫败感、注意力和情绪体验；
- 真实辅助技术用户体验。

代理对提示使用很重：221 次解题循环都请求了完整的一级、二级、三级提示链。因此，本报告对“提示链可执行”和“UI 可完成”提供强证据，但不能把这一结果解释为无提示独立可玩性或儿童验证。儿童观察、成人陪伴观察和真实辅助技术验证仍须另行执行。
