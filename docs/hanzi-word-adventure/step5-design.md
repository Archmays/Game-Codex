# 字间行者 STEP5：结伴归途与连续操作

儿童体验问题：一个人切换两个行路人时，能否始终看清谁在走、谁在举灯、哪只手可搬字，并用连续的动作把两人一起带回家？本轮只增加双角色分工这一族规则。原三章十五房保持单角色、原布局、原材料和原存档结构；没有联网、自动跟随、背包传送、新字考核或麦克风。

## 纯规则与五房

| 稳定ID | 有实际作用的分工 | 精修依据 |
| --- | --- | --- |
| companions-1 | 单廊上人拿木让路，友拿明让路并照亮折向双家的影格；两人各有一件在手 | 首稿友可直接站家等待；改成两种不能直接合并的实体堵住窄廊，实际求解包含双方拿字。九列改为七列折向下，保留手机44像素格 |
| companions-2 | 前方的人运木铺桥，后方的人携明跟进照亮两段窄影路；前方不能独自用原地灯完成架桥 | 首稿一人能先架桥再回来取灯；改为初始光照不足的连续暗廊和窄岸，使另一双手有实际用途 |
| companions-3 | 明与林分别运输；拆林后腾出的手分两次铺木桥，影与水交错迫使举灯者中途跟进 | 初稿日月与林加大空岸超过40000状态；复用已合成的明并裁去无关岸格，保留拆林和双桥运输；再将两桥间的一格改为影，让举灯者必须在第二趟运输前跟进，而非末尾才拿灯 |
| companions-4 | 两岸暂不连通。人侧门句打开友侧的门；友侧风句停住人侧的风 | 首稿仅一人做完门风，另一人只是追加出口目标；改为双方必须为伙伴改规则。门、风绑定可点句查看连线 |
| companions-5 | 灯与有限不、木分工运输；停风直走和留风架水桥两种策略 | 初稿宽岸及林增加过多无关排列；改为一枚桥木并裁岸，保持两条机制不同的策略，而非换走路顺序 |

每间恰有两格家，标作家1和家2，任意角色可占任意一格。先到家的人仍占格，也能离开；只有双方分别站在家格才完成。世界中人/友完整字形与地形、木桥分层显示，控制者用圆圈、等待者用方框；并列角色按钮同时写明正在走/等在原地、各自手持与到家状态，不能仅靠颜色辨认。首次完整触控图发现已占家格重复画大“家”与家编号，形成“友家/人家”贴字；已改为角色居中、底部只留家1/家2，保持影/桥原分层不变。赢态目标说明改为到家与下一间，不再指向身后的山格。

`WorldState.player` 始终表示当前控制格，只有结伴章拥有 `companion` 与 `active`。实体仅在新章手持时拥有 `holder`。切换交换两个控制坐标并改变 active，实体所有者与绝对位置保持；光源按实际持有人所在格计算。双方每人最多一件，交换必须落地再拿。同一 `act` 处理原子移动、拿放、拆合、碰撞、光、门风和胜利，不复制旧引擎。

拒绝说明点名实际受影响的人或友；单人章仍只说人。有实体但不安全拿走时明确“暂不能拿”，不把它误说成没有字。任何实体变化和移动后的候选状态都检查双方落脚；不能抽掉伙伴桥木、关闭其脚下门或移走其影格光源。风沿用原主角色有效动作后的结算语义；切换提前返回，不结算风。若拿不重新开风会吹动未控制伙伴，整步拒绝并提示先把伙伴移开，不能自动移动等待者。撤销和刷新包含完整角色位置、控制身份、材料所有者、光的输入与胜利。

求解仍是40000状态上限的操作层BFS加有向步行闭包；等价键保留控制身份、等待者位置、每件物品的持有人，只合并与实际规则等价的木身份。每条边保留真实移动/切换/变换动作。`solve-step5.ts` 搜索并回放全部二十房，额外用“禁止架水桥”与“禁止放不进风句”分别求末房两解。未知上限与穷尽无解保持不同；三级提示先回放到第一个材料动作前，按当时角色的手持物说明，三级仍描述真正下一步，包括先按Q。

## 连续操作修订

Space/E默认拿或放当前明确目标，不因林、明或可合材料跳进菜单，也不调用求解器猜答案。X直接开拆分预览，C直接合；预览内左右选择落格、Enter/Space/E确认、Esc取消。成功、取消和指针世界动作回到世界，方向键可立即继续；Tab仍可主动离开。世界触发的H提示与Esc关闭回世界；主动Tab原生提示按钮打开后，键盘关闭回开关按钮；指针关闭回世界。动作按钮首次创建后复用，只改文字、隐藏和disabled，不在重绘时销毁控件。

原生按钮、编辑域、IME、Ctrl/Meta/Alt组合键保持共享过滤；被消费的Space不会穿透到下房。变换的repeat不执行，移动repeat保留170ms节奏；动画不再吞掉独立的新按键。blur/hidden/pointercancel清理残留输入。手机方向区和主操作紧邻，两人状态放在操作区顶部，低高度仍正常滚动和缩放。

## 独立保存与集中入口

新键精确为 `family-games/hanzi-word-adventure/companions/v1`，结构 `{version:1, journey, settings}`。旧 `v2` 只接受原三章，明确拒绝把companion写入旧结构。直接 `?play=hanzi-word-adventure&chapter=companions` 只选择继续，不重置；即使只有旧v1，直接新章也不会额外创建旧v2。菜单仍能读到旧章节，再明确选旧章时才恢复其保存路径。切换前先保存当前模式。坏/未来结构或其他页/Vault已改写的槽保留原文；重开仅在内存可玩，不能借重开覆盖未知原文。原文比较与未知顶层设置字段保留沿用旧原则。

共享Vault登记、本次试玩页面和发布由STEP5整合者统一处理。没有第二套反馈平台、身份信息、输入轨迹、云端上传或ZIP。
