# 字阵守城

## 游戏目标
守住青岚关的一条弯曲来路，在六波怪物进攻中部署字核、合字、组词。入口 `?play=hanzi-tower-defense`；第一屏就是战场，开局有火塔和五枚材料。

## 适合对象
可在需要时一起读字、讨论塔位的家庭玩家。界面提供读音、短释义和部件位置；机器检查不证明儿童乐趣或学习效果。

## 玩法说明
点材料或已部署的字核，再点空塔位部署。选两枚字核先看组合预览，再确认；材料点击顺序不限，配方决定规范结构和词序。背包＋背包回背包，背包＋字塔替换该塔；两塔组合明确保留／释放位置，可切换保留哪座来源塔。拖到已占塔位同样先预览、再确认，落点为目标，不吞第三枚材料。上下合成炎，左右合成林／沐；火山、山林保留完整双字和词序。错误组合不扣材料；选一枚即显示搭配与缺料原因，亮起的搭档可直接选择。

指向、聚焦或点选字塔查看攻击范围，不受合成材料顺序影响。选一枚字核后，指向／聚焦空位可预览部署覆盖，触屏点空位直接部署；部署、合成后保留产物查看。显示全部射程默认关闭，仅为本页查看选项，不写存档。范围 SVG 使用真实塔位、`CORES[kind].range` 和地图坐标变换；边界表示寻敌距离，不代表命中后的爆炸／减速扩散。

每波材料袋含火、木、氵、山各一枚和一枚种子变体；五次掉落自动入栏，无容量上限。开局即有可用合成。两条竞争路线为炎＋山林及火山＋林；可混合使用沐。塔位影响路径覆盖，字核决定攻击、射程、溅射和减速。多余背包材料仅可修补本局城门，满血时不消耗，不产生货币或材料回购循环。

波间由玩家启动下一波，没有倒计时；战中可暂停部署。失败可立即重开，配方发现保留。约四分钟有效战斗加部署／组合时间，目标一局约 5–8 分钟；不强制等待。

## 涉及知识点
材料和完整字不同：氵标为“非成字部件／三点水”；不将它作为独立整字认读。九条内容记录和五条配方见 `content.ts`，逐条绑定汉典条目、字形、位置、读音、简义、熟悉词和视觉说明。沐为氵旁木声；水波／藤蔓／熔岩等仅是法术设计，不解释为字源。

## 设备适配
鼠标点击及拖放、触控点选、Tab／Enter 键盘操作；P 暂停、Esc 放回选择。小屏允许页面自然滚动，字塔保留可操作尺寸。静音和减少动态独立保存；隐藏页面自动暂停并停止声音，回来需主动继续。没有麦克风请求、识别 SDK、录音、账户或网络遥测。

## 当前完成度
一张地图、八个塔位、六波、三类敌人、三条合字、两条组词。Phaser 表现层使用同一个固定步长战斗模型；表现特效不修改规则。最小素材来源为新生成草地城关背景、Kenney CC0 敌人部件和塔基，详情见 `assets/images/hanzi-tower-defense/manifest.json`。本次报告在 `docs/hanzi-tower-defense/step1-report.md`。

## 接入方式
`index.ts` 导出标准 `GameDefinition` 及独立 `mountHanziTowerDefense`，挂载仍为现有 Vite＋TypeScript＋Phaser。存档唯一键 `family-games/hanzi-tower-defense/v1`。战中只保存波前检查点和非经济性的已发现配方，刷新重打未完成波次，掉落与材料消耗一起回滚，不复制奖励、不跳波。波间部署即时入检查点。损坏／未来／其他页面改写的记录不被覆盖，仍可本页游玩。任何旧语言或数学存档均不读取、不迁移。

## 后续改进建议
以下是已固定方向，本次不实现，也不显示空入口：

- 下一款解谜的世界视觉主要由文字构成；文字同时是地形、对象和局部规则，不是插画贴汉字。本次不建空壳。
- 后续同义中文词＋英文词装入同塔产生稳定共鸣；正确说出两种目标词可短时提高该塔攻速。
- 语音模式须完成明确授权，随开始游戏启动，前台期间持续监听；不逐次点击、不先选塔、不手动切语言。双语词自动匹配塔，同名多塔确定性选择一座就绪塔，去重并受冷却限制。不中断战斗判题，不因环境对话反复暂停；常显监听／静音状态。
- 离开、隐藏、锁屏或静音时停止采集并释放资源；恢复符合已选模式和浏览器授权。处理识别会话中断，不把 `continuous=true` 当永不中断保证；抑制示范音／音效自触发。不储存录音或对话，不将识别命中冒充严格发音评测。云端音频处理必须另行明确授权，不能静默降级。
- 本次不请求麦克风，不添加语音 SDK、模型或后端，也不因未来语音兼容性阻塞交付。
